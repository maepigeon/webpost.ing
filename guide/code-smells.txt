CODE SMELLS — webpost.ing
Last updated: 2026-09-08

Quality issues, not bugs. Nothing here is broken; all of it makes the codebase
harder to change than it needs to be. Ordered by how much trouble it is likely
to cause.

Bugs and vulnerabilities are tracked separately, in guide/SECURITY.md and
guide/tasks.md.

FIXED items are kept for one revision so the pattern is recognisable next time,
then dropped.


================================================================================
1. THREE COMPETING MIGRATION SYSTEMS                                     [HIGH]
================================================================================

  tools/migrations/         014,015,016 .sql   tracked in `_migrations`
  config/migrations/        V001..V010  .sql   tracked in `schema_migrations`
  server/.../db/migrations/ V001..V013  .sql   tracked in `schema_migrations`

Only the third runs in production — DatabaseMigrationService applies it from the
classpath at startup. The other two are shell-driven and reachable by hand.

config/migrations/ is three versions BEHIND the ones that actually ship, so
`./config/migrate.sh` against a fresh database produces a schema the app will
reject. guide/MIGRATIONS.md claims the two directories hold "the same files".
tools/migrate.sh is an older generation entirely, with a different tracking
table and a different file-naming convention.

Fix: keep server/src/main/resources/db/migrations/ as the single source. Delete
tools/, and either delete config/migrations/ or make it a symlink. Point
MIGRATIONS.md and README.md at whichever survives.

Risk if left: someone runs the wrong script against production and half-applies
a schema, with two tracking tables disagreeing about what happened.

2. 132 INLINE style={{...}} BLOCKS ACROSS THE CLIENT                     [HIGH]
================================================================================

  33  PostsViewer.jsx        (was 42; the profile-maker ones are now CSS)
  17  AdminPanel.jsx
  14  MessagesPage.jsx
  14  Viewer.jsx
  10  Editor.jsx
   9  Logout.jsx
  ... 132 total

Inline styles cannot use the --neo-* variables, cannot be reused, and cannot
express :hover, :active or media queries — so every one of them is a small
divergence from the design system. This is the single biggest reason the UI
reads as generic: the style guide describes a coherent neoskeuomorphic glass
language that inline styles quietly opt out of.

Fix: move to component CSS files, as done for the profile maker
(ProfileEditor.css). Highest value per file: AdminPanel.jsx, MessagesPage.jsx.

4. deploy.sh DESCRIBED A SERVER THAT DOES NOT EXIST                   [FIXED]
================================================================================

The old script killed the JVM by port and started a replacement with nohup as
the invoking user. On the real host systemd owns the process, so that produced a
second unmanaged server and a "port already in use" error — and `lsof` as a
normal user cannot see the root-owned listener, so the port looked free.

It also never copied anything to /var/www/webpost.ing/html/ or
/home/webpost.ing/, meaning a "successful deploy" published nothing.

Now reads deploy.env, publishes both artifacts, restarts via systemctl, and has
--dry-run. See guide/DEPLOYMENT.md.

================================================================================

================================================================================
7. NO SHARED AUTHORIZATION HELPER IN THE CONTROLLERS                   [MEDIUM]
================================================================================

This shape is repeated 80+ times across five controllers:

    AuthSession session;
    try { session = loginRepository.authorize(username, token); }
    catch (JdbcLoginRepository.TokenExpiredException e) {
        return ResponseEntity.status(HttpStatus.UNAUTHORIZED).body("Session expired");
    }
    if (session == null) return ResponseEntity.status(HttpStatus.UNAUTHORIZED).build();

Every copy is a chance to get it subtly wrong — and the copies already differ in
status code and body. The audit had to read all 80 to be sure none was missing.

Fix: one `requireSession(username, token)` helper (or a small
HandlerInterceptor) returning a session or throwing a mapped exception.
AdminController already has `isAdmin()`, which is the right instinct.


================================================================================
8. /api/authorizeSession SIGNALS FAILURE WITH HTTP 200                 [MEDIUM]
================================================================================

An unauthorized session check returns 200 with an empty body; the client infers
logged-out from the empty string:

    if (response.data == null || response.data == "") { ...log out... }

That is why "stale token -> HTTP 200" appears when probing the API, and it makes
every session check indistinguishable from success to anything but this one
client. Should be 401.

Ties into the open task "auto-log out if session expired or not logged in" —
worth doing together, since a 401 interceptor is the natural implementation.

================================================================================

UploadController wraps the quota lookup in
`catch (Exception e) { /* allow the upload */ }`. Deliberate and commented, but
a database hiccup lets a user past their storage limit. Rejecting is the safer
default. Also noted in guide/SECURITY.md finding 11.
